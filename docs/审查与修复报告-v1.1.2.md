最严重的三条：

1. **整场板书写进别的页**：`OnPresentationStart` 里 `CurrentSlide` 已是起始页，`ApplySlideIndex` 判定"没变化"不派事件，S1 从不 `SwitchPage`；页码轮询又因 session 已等于当前页而无法纠正。
2. **COM 事件永远收不到**：专用 STA 线程只有阻塞队列、没有消息泵，ConnectionPoint 的跨套间回调无人派发，同时 PPT 侧等待一个永不泵消息的线程。
3. **亮度键翻页必崩**（本轮发现）：`RAWHID.bRawData` 是**内联字节数组**，却按 `IntPtr` 反序列化后 `Marshal.Copy`，等于把 HID 数据当指针读 —— 访问违例无法被 `catch` 捕获，直接杀进程。

## 2. P0：主流程阻断

### P0-1 放映页不同步（已修复）
- 证据：`UI/UiOrchestrator.cs` S1 分支；`Core/AppStateMachine.cs::OnPresentationStart`。
- 根因：新建 session 时 `CurrentSlide` 已写入起始页 → `InkEngine.ApplySlideIndex` 返回 `null`（无变化）→ `SlideIndexChanged` 不触发 → 引擎停在上一场/手动书写的页。
- 修复：S1 在换课件检测之后**无条件** `SwitchPage(session.CurrentSlide ?? 1)`；S0 与手动唤起同时复位 `_lastBadgePage/_lastBadgeTotal` 与页码缓存，手动唤起回到第 1 页。
- 位置：`src/PptInk.App/UI/UiOrchestrator.cs:546-552`、`:617-625`。

### P0-2 COM 主通道无消息泵（已修复）
- 证据：原 `Detection/ComWatcher.cs` 用 `BlockingCollection.TryTake` 驱动 STA 线程。
- 根因：`IConnectionPoint::Advise` 的 sink 回调必须由订阅线程的消息循环派发；无泵 = 事件丢失 + PPT 侧被反向拖住。
- 修复：专用 STA 改为 `Dispatcher.CurrentDispatcher + Dispatcher.Run()`；绑定/退订/RCW 释放全部投递到该线程；新增 `ProbeHealth()`（`SlideShowWindows.Count` + `Name`）与 `Unbound` 事件；`Dispose()` 在 STA 上带 1s 超时同步退订后再关泵。
- 位置：`src/PptInk.App/Detection/ComWatcher.cs`（整体重写）。

### P0-3 手掌抑制只覆盖通道 A（已修复）
- 证据：通道 B/C 的 Down 无条件放行；通道 A 在标准 Windows 常收不到消息。
- 修复：
  - `UnifiedStageWindow.Ink.cs`：新增 `_touchPalmById`（`TouchDevice.Id → 是否手掌`）与 `_palmBlockUntilTick`（120ms 抢先抑制窗口）；`RawInkPlugIn.SuppressInkForDevice` 参与 Down 判定。
  - `UnifiedStageWindow.InkInput.cs`：`PreviewTouchDown/Move/Up` 用 `TouchPoint.Size` 换算物理矩形，调用既有的 `PalmRejection.ShouldAcceptInk`；判为手掌时同时置 `_touchOwnedUntil`。
- 位置：`src/PptInk.App/UI/UnifiedStageWindow.Ink.cs:51-52, 87, 103-105, 432, 452`；`UnifiedStageWindow.InkInput.cs:480-523`。

### P0-4 亮度键翻页访问违例（本轮新发现，已修复）
- 证据：`Core/BrightnessHotkeyRouter.cs` 原实现 `RAWHID` 含 `IntPtr bRawData` + `Marshal.Copy(hid.bRawData, ...)`。
- 根因：Win32 `RAWHID` 的 `bRawData` 是紧随 `dwCount` 的**内联字节数组**，不是指针；按指针读取 = 任意地址拷贝，AccessViolation 不可捕获。
- 修复：改用 `Marshal.ReadInt32(hidPtr)` / `ReadInt32(hidPtr, 4)` 读取 `dwSizeHid/dwCount`，从 `hidPtr + 8` 拷贝，并增加 `bytes` 与报告实际长度（`size - headerSize - 8`）的边界校验。
- 附带：删除单字节 usage 兜底扫描（任意 HID 报告里的 `0x6F/0x70` 字节会造成随机翻页）。
- 位置：`src/PptInk.App/Core/BrightnessHotkeyRouter.cs:96-106, 124-136`。

### 5.2 Beta AI 融合（默认关闭的稳定可选功能）

### 5.3 AI Python 桥优化（本轮）
- 缺依赖不再直接退出：`numpy` / `pptink_recog` 导入失败时桥保持可服务，`hello/ping` 回报 `numpy/recognizer/numpy_error`；`recognize` 返回 `numpy_missing` / `recognizer_unavailable`。

- 新增 `ping`（pid/uptime/统计/依赖）与 `warmup`（首次调用开销前移）；握手成功后同步预热并完整读回响应，避免协议行错位。
- 超长笔画等距抽稀到 1200 点再发送（引擎本身 4px 重采样），降低序列化/IPC/解析成本。
- 崩溃限流修正：首次拉起不计入 3 次/分钟；依赖缺失回滚计数，装好 NumPy 后不需要再等一分钟。
- 单行协议上限 4MB；识别算法异常只让本次请求失败，不杀常驻进程。
- 位置：`python/ink_bridge.py`、`src/PptInk.App/Bridge/PythonBridge.cs`、`BridgeProbe.cs`。

## 7. 尚存风险与建议

1. **`ComWatcher.Start()` 3 秒内未就绪**只记日志、不重试；依赖检测器每 5s 的 `TryBind()` 兜底，但首场放映可能晚一拍。建议改为在 `_dispatcherReady` 上挂超时重试。
2. **`Dispose` 与 `ManualResetEventSlim` 竞态**：`_disposed` 与 `_ready.Wait` 之间仍有极窄窗口可能抛 `ObjectDisposedException`（已被上层吞掉，但会多一条日志）。
3. **媒体键全局接管**意味着放映中音量键不能调音量（符合本次需求，默认开）。若真机反馈强烈，建议改成"仅当 PPT 不响应标准翻页键时才接管媒体键"。
4. **亮度键**只在 OEM 把亮度键上报为 HID Consumer Control 时有效；笔记本 EC 直接处理时无法拦截（属窗口系统限制，文档需注明）。
5. **Beta 几何后处理**的容差（4mm 缝隙、6mm 接续）未必适配所有屏幕尺寸，建议真机按 `PxPerMm` 复核一次。
