# PptInk 工程审计与整改报告

审计基线：v0.9.2；本轮源码版本标记：v0.9.3（待 Windows Release 构建验证）  
审计日期：2026-10-20  
审计方式：静态源码检查、Python 自动测试、配置/清单解析、边界情况审阅。当前执行环境未安装 .NET SDK，也不是 Windows；**C# 编译、触控/COM/WPF 真机验证尚未完成**。

> 版本说明：这份报告记录的是 2026-10-20 的历史审计基线，不是本轮 v0.9.6 交互/设置增强的编译报告。当前版本新增项与本轮验证状态请同时阅读 `触摸交互整改说明.md` 和 `设置中心与交互体验增强说明.md`。

## 1. 结论摘要

项目覆盖的技术边界较宽，已有一些正确的工程意识：单窗口分层、按需拉起 AI、日志缓冲、有限长度笔迹、撤销历史以及识别回归测试。整体不宜再以大规模重写为第一选择，应优先建立可复现的发布门禁，再持续减小高耦合 UI 与平台原生代码的回归风险。

本轮修复聚焦会丢配置、墨点消失、边界擦除、AI 子进程生命周期、插件输入边界和发布可验证性。**没有证据支持“零错误”“全面兼容所有希沃机型”或“已达到苹果级体验”的结论**；这些需要真实设备矩阵、用户任务测试、性能采样与可重复的 Release 构建。

## 2. 本轮已修改

| 领域 | 修改 | 价值 |
|---|---|---|
| 配置持久化 | JSON 配置显式支持 `NaN`/`Infinity` 字面值，与布局“尚未定位”哨兵一致；临时文件完整写入后原子替换；保存失败可写入诊断日志 | 防止默认配置因 NaN 序列化失败而无法保存；降低断电/异常导致配置被截断的风险 |
| 配置校验 | 加入有限数、尺寸、模式、颜色、停靠位置等归一化 | 旧配置或人工编辑的异常值不会直接进入渲染和输入链路 |
| 点墨与导出 | 页面缓存不再跳过单点笔迹；SVG/PNG 对轻触与近零位移笔迹统一导出为圆点；速度笔锋最小宽度与实时绘制口径对齐；SVG 使用不变区域格式化并限制颜色字段 | 修复墨点在缓存重合成与 PNG 导出中丢失、快速笔锋过细不可见、部分区域设置下 SVG 小数格式错误的风险 |
| 输入与渲染坐标 | 将 WM_POINTER、WPF Stylus、鼠标/触摸提升三路输入统一映射到 3840×2160 逻辑墨迹空间；缓存按文档尺寸创建，实时绘制、落笔后缓存、橡皮提示与导出共用同一几何口径；DPI/视口比例变化会触发重合成 | 降低 1080p/4K、多 DPI、抬笔后和导出时笔迹位置/粗细跳变、缩放后缓存失真的风险 |
| 希沃设备探测 | 按 Windows SDK 修正 `POINTER_DEVICE_INFO` 字段与结构步长；通过 `GetPointerDeviceRects` 独立取得触摸物理范围和映射显示分辨率；只有与放映屏匹配时才使用物理校准，否则回退机型档案 | 避免错误的原生结构步长导致探测无效/内存写错位；减少笔记本与希沃大屏双屏部署时串用错误尺寸的风险 |
| 书写生命周期 | A/B/C 输入会话使用“落笔占有—收笔提交—释放”状态；舞台停用进入阻断哨兵，重新激活才恢复空闲；B 通道 Down/Move/Up 与 ForceLift 共用生命周期门闩 | 降低快速抬落笔、模式/舞台切换与迟到报点造成的跨笔串接、幽灵笔迹和隐藏半笔风险 |
| 渲染调度与反馈 | 重绘请求按帧合并到最多一个待处理 Dispatcher 请求；落笔反馈计时器明确调度到窗口 UI Dispatcher | 避免高频输入在 UI 忙碌时堆积过期重绘任务；修复反馈泵可能绑定到非 UI 线程 Dispatcher 的风险，提升跟手性与反馈确定性 |
| 区域擦除 | 对擦除、快照、恢复矩形统一做有限数检查和位图裁剪；拒绝尺寸不匹配的快照 | 降低越界矩形、零面积或损坏历史快照导致异常/内存越界的风险 |
| AI 桥 | 请求点集验证、每行请求都返回 JSON 响应、请求异常不使服务进程直接退出；C# 侧增加响应/握手超时、启动失败清理，以及 AI 关闭后禁止启动/重连 | 异常输入与进程退出时的恢复行为更可预测，避免请求无限等待或退出后重启子进程 |
| 墨迹时间戳 | AI 重建点序列改为沿用原始笔迹时钟区间，而不再给每个点打不同系统时钟域的时间戳 | 避免规整后笔锋宽度和滤波结果受 AI 返回处理速度影响 |
| 插件边界 | ZIP 安装先检查路径、文件数与解压尺寸；先校验 staging 内容再替换安装目录；更新失败尽力回滚；ID 比较不区分大小写 | 降低越界路径、压缩炸弹、覆盖有效插件和 ID 大小写绕过风险 |
| 插件运行 | 插件异常被宿主捕获并记录；修复大小写兼容、面板 API 未注入、FREE/DRAW 插件误调 `onActivate` 导致 `onStart` 不执行的问题；限制面板尺寸/滑条范围/元素数量、Lua 折线点集和最多 32 个计时器；Lua 顶层、事件和定时器回调设置协程指令/时间预算，超限自动隔离；停用关闭面板不再重复触发停用回调；截图仅写入该插件数据目录 | 降低插件“已启用但无行为”、脚本错误污染 UI/渲染状态、无限循环卡 UI、重复清理副作用或通过截图接口覆写任意文件的风险 |
| 生命周期与诊断 | 控制管道支持取消；退出时各服务独立清理；日志刷盘串行化，并在正常退出时尝试落盘 | 单个清理异常不再跳过其余资源释放，降低常驻任务/尾部日志丢失风险 |
| 工程化与交付 | 新增源码构建说明、开发依赖文件、Windows + Python CI 门禁、`scripts/build-portable.ps1` 自包含 x64 发布脚本和 artifact 上传步骤 | 建立可复现的后续 Release/便携包产出路径；当前容器未执行 Windows workflow，因此不能声称已经得到已编译包 |

**Lua 执行预算说明：**本轮基于 MoonSharp 协程的 `AutoYieldCounter` 机制将脚本分段交还宿主，并在每段之间检查指令片数与墙钟时间；这能阻止常见纯 Lua 无限循环长期独占 UI 线程，但不构成操作系统级沙箱。官方说明也明确指出，进入不可让出的原生回调时不能保证立即抢占。参考：[MoonSharp 协程与自动让出](https://www.moonsharp.org/coroutines.html)。

## 4. 尚存风险与建议优先级

### P0 — 发布前必须完成

1. **Windows Release 构建与安装包验证。** 本轮修改了 C# 关键代码，但没有本地 .NET SDK 可编译；必须先让 Windows CI 通过，任何编译错误都应先修复。当前归档不含 exe、嵌入式 Python 运行时和安装器，不能当作便携二进制发布。
2. **触控与穿透兼容矩阵。** 本轮已将三类输入通道统一到 3840×2160 逻辑墨迹坐标、按 Windows SDK 结构修正触摸设备探测，并调整自动档案选择，避免 4K 大屏在触摸元数据缺失时被高 DPI 启发式误判成笔记本。以上属于源码修复；覆盖 Windows 10/11、常见缩放组合、扩展屏、不同显卡驱动、希沃红外大屏和普通触摸屏仍须在真机验证。验证书写、触摸穿透、按钮命中、屏幕切换以及结束放映回收。
3. **墨迹数据完整性。** 真机验证连续书写、单点、快速抬落笔、撤销/重做、三类擦除、退出恢复、SVG/PNG/JSON 导出和长课时内存变化；对 120/240Hz 设备采集重绘队列长度、有效帧率和书写到屏幕延迟，确认帧合并策略在真实报点负载下有效。
4. **PowerPoint COM 故障恢复。** 打开/关闭/崩溃/重开 PPT、快速翻页、演讲者视图、多实例、未安装或启动中的 PowerPoint 都要有可复现结果。

### P1 — 高优先级

1. **建立真实笔迹识别语料。** 当前识别率阈值主要针对合成样本。应采集经用户同意、去标识化的真实手绘线、箭头、勾叉、椭圆和多边形，并记录各形状精确率/召回率、误规整率和延迟分位数。教育现场错误规整会比漏识别更影响信任。
2. **性能预算。** 至少在 1080p / 4K、多屏和长时间课堂场景测量：书写端到端延迟、掉点率、渲染帧时间、单页笔迹数上限、擦除峰值耗时、AI 冷启动、内存与句柄增长。
3. **静态画布尺寸策略。** `InkDocument` 当前标准文档坐标为 3840×2160，并按实际舞台视口缩放；这比缓存采用屏幕大小、输入却采用另一套坐标更一致。仍需真机确认 16:9 以外的投影比例、窗口异常尺寸和已有数据升级策略是否符合预期。
4. **插件能力契约。** `DrawText` 当前仍通过 Toast 展示占位，而不是在画布上形成可编辑文本对象；`network` 权限也没有对应网络 API。应明确记录未实现的能力，避免插件作者误以为其已具备完整语义。
5. **设置保存反馈。** 目前保存失败被写入日志而不是 UI 明示。高可靠版本可增加状态提示/重试，并在配置损坏时保留 `.corrupt` 备份以便恢复。

### P2 — 品质与维护性

- 拆分 `SettingsWindow.cs`、`Toolbar.cs` 和统一舞台协调器中仍较大的职责；为状态机、历史树、配置归一化、插件包验证增加独立单元测试。
- 为 C# 引入统一分析器/格式化规则和 nullable 警告门禁；对 P/Invoke 标注正确的 `SetLastError`、结构体布局、位数假设，并集中管理 Win32 常量。
- 建立无障碍和触屏可用性验收：44px 以上主要命中目标、键盘可达、焦点可见、对比度、文本缩放、减少动画选项。
- 建立可复现打包流程：锁定 Python 依赖、记录版本与哈希、验证 x64 与签名、生成 SHA256 清单、发布升级/回滚方案。

## 5. 推荐的发布验收标准

- Windows Release 构建无错误；测试门禁全绿。
- 连续 2 小时书写/翻页/擦除测试无 UI 卡死、句柄持续增长或异常丢迹。
- 触控、鼠标和交互穿透场景分别记录通过矩阵；未通过的组合明确降级提示，不以“兼容所有设备”描述。
- 识别以真实样本报告 precision/recall 和误规整率，不只报告合成测试通过。
- 更新包安装失败不破坏上一版本；用户配置损坏可恢复；退出时进程、钩子、定时器、管道、托盘和日志均能闭环释放。
- 以课堂教师任务测试验证体验：第一次进入能否自助完成、误操作是否可撤销、学生触摸是否干扰、视觉干扰是否可控、连续高压使用是否稳定。
