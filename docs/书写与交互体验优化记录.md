# PptInk v0.9.7 书写与交互体验优化记录

本轮针对用户反馈的 7 项问题逐条修复。与前几轮"仅静态校验"不同，本轮在 Linux 环境用

## 问题 2 · 工具栏显示与设置内设置不一致

**现象**：设置里勾选了 9 个元素，但工具栏只显示「笔/荧光笔/触摸/擦除」四个，
撤销、重做、AI、插件全部不可见。

**根因**：工具栏的「分割副岛」机制中，`ToolbarSplitAfterId` 被持久化为 `"erase"` 后，
主栏在 `erase` 之后截断，Ops 段（undo/redo/ai/plugin）本应进副岛；但当副岛因
旧配置元素全隐藏、或时序问题未能创建时，这些按钮**既不在主栏也不在副岛**，
形成无法自助恢复的黑洞状态。

**修复**：三层自愈，任一层命中即可恢复。

| 层 | 文件 | 逻辑 |
|----|------|------|
| 启动期 | `Core/AppConfig.cs` `NormalizeToolbarLayout` | Ops 组四项全隐藏 → 重置为可见；分割点后无可见元素 → 清除分割标记 |
| 重建期 | `UI/Toolbar.Layout.cs` `RebuildLayout` | 分割标记存在但 `SplitSegmentItems()` 为空 → 清除标记 + 保存，本帧即以一体化渲染 |
| 副岛期 | `UI/UiOrchestrator.Islands.cs` `RebuildSegment` | 副岛构建时元素为空 → 清标记 + `RebuildLayout` + Toast 提示用户 |

设置中心「工具栏」页另增：

- 「恢复默认布局」现在同时清除分割标记；
- 处于分割态时显示「合并副岛回主栏」快捷按钮（用户找不到副岛时的自助路径）。

## 问题 3 · 笔悬浮面板只显示红黄 2 色

**现象**：笔的浮岛调色板只出现红、黄两色（用户误以为是荧光笔的颜色），
与设置中心的默认画笔颜色不一致。

**根因**：`Toolbar.Palette.cs` 的 `RefreshPaletteRecent` 只渲染 `Config.RecentColors`
（用户最近书写沉淀），为空时回退硬编码的 `PaletteSuggest`（5 色）；用户刚装好软件
没有书写记录，于是只看到推荐色的前几项，且与设置中心完全脱节。

**修复**：`src/PptInk.App/UI/Toolbar.Palette.cs`

- 新增 `PenPresets`（8 色：朱红/明黄/天蓝/青绿/白/紫/橙/墨黑）与
  `HighlighterPresets`（5 色：荧光黄/薄荷绿/冰蓝/柔粉/杏橙），**与设置中心
  「画笔」页的色板同源**。
- `GetPaletteColors(tool)` 按工具返回色板：笔 = 最近用色（去重）+ 8 色预设；
  荧光笔 = 5 色预设。
- `ShowPalette(tool)` 记录 `_paletteTool`，据此设置标题（画笔设置 / 荧光笔设置）、
  当前色、RGB 滑块与预览 —— 切工具再开浮岛不残留上次颜色。
- `ApplyPalettePen` 按工具分流：笔写 `InkEngine.Pen`；荧光笔写 `Config.HighlightColor`
  与 `InkEngine.Pen.ThicknessMm`（不污染普通笔的 `Highlighter` 状态）。
- 选中色高亮圈跟随 `_paletteColor`；仅在拾取色板颜色时刷新（避免拖动 RGB 滑块
  每帧重建色板造成对象分配风暴）。

## 问题 4 · AI bridge 未检测到

**现象**：设置中心「快速检测 AI 功能」报「AI 桥未检测到 / 工作不正常」。

**根因**（三重）：

1. `BridgeDir` 只探测 `<exe>\bridge\` 单一路径，便携包变体 / 开发仓库
   （`python\ink_bridge.py`）探测不到；
2. 握手超时 15s 偏紧 —— 嵌入式 Python 冷启动 + NumPy import 在低配大屏、
   杀软扫描下实测可达 18~22s，正常环境被误判为超时；
3. 嵌入式运行时缺失时静默回退系统 Python，系统 Python 未装 NumPy 时握手能过、
   识别报错，用户只看到模糊的「未检测到」。

**修复**：`src/PptInk.App/Bridge/PythonBridge.cs`

- `BridgeDir` 按序探测 `bridge\` / `python\` / `..\python\` / `..\..\..\python\` / `exeDir`，
  第一个含 `ink_bridge.py` 的目录胜出，全不命中则回退首选布局以给出明确路径。
- `RestartProcess` 握手超时 15s → **25s**；`CheckHealthAsync` 超时 18s → **28s**。
- 嵌入式运行时缺失时写明确警告日志，提示运行「快速检测 AI 功能」验证依赖。

**实测**（本环境，Linux Python 模拟 C# 端协议）：

```
1) 握手: {'ok': True, 'server': 'pptink-bridge', 'version': 2, ...}
2) 圆形识别: circle 置信度: 0.999
3) 矩形识别: quad
5) 关闭: {"ok": true, "bye": true}
```

## 问题 5 · 擦除性能（4K 掉帧）

**现象**：擦除（尤其长手势）明显卡顿。

**根因**（三重叠加）：

1. `ErasePartial` 每个 Move 事件都用**完整累积路径**对命中笔做 O(n×m) 逐点逐段扫描，
   m（路径点数）随时间线性增长；
2. `HitByErasePath` 无包围盒预筛，屏幕上所有笔全量扫描；
3. 每次擦除导致 `Strokes.Count` 变化 → `RecompositeNeeded` 判定为真 →
   每 Move 一次 4K 整页缓存重合成（960 万像素 Clear+Render），这才是掉帧主因。

**修复**：

`src/PptInk.App/Ink/EraseService.cs`

- 引入 `_pixelPathCursor` 游标，像素擦除只对**自上次以来的新增路径段**切分；
- `HitByPathFast`：先比较笔包围盒与路径段包围盒（含半径外扩），不相交 O(1) 跳过；
- `SplitStroke`：逐点判定前先用路径包围盒粗筛，笔上远离橡皮的点 O(1) 跳过；
- `FlushErase` 重置游标，会话间不串扰。

`src/PptInk.App/Ink/InkEngine.cs`

- 擦除判定节流至 ~125Hz（`EraseExecIntervalMs = 8`）；路径仍持续记录不丢精度，
  `Invalidate` 仍每 Move 触发以保证橡皮圈光标跟手。

`src/PptInk.App/UI/UnifiedStageWindow.InkRender.cs`

- `RecompositeNeeded` 在擦除手势激活期间（路径点存在）跳过 `StrokeCount` 变化引发的
  整页重合成；被切分的笔由 ghost 层以淡出呈现，抬笔时一次性重合成。
  形成「笔迹正被擦掉」的渐隐过渡，比「闪没+淡出」更柔和。

## 问题 7 · 笔墨流畅感、舒适感、笔锋与惯性

**现象**：书写缺乏流畅感与舒适感，无笔墨惯性、无笔锋。

**根因**：

1. 固定 EMA 滤波 —— 慢写抖动、快写滞后，无法兼顾；
2. 无起笔/收笔的笔锋形态（真实笔墨落笔由细到粗、提笔由粗到细）；
3. 渲染用 `PolyLineSegment` 折线拼接，笔画是硬折角而非圆润曲线；
4. 宽度低通系数固定 0.45，快写笔锋变化迟钝、慢写又易受微小速度波动影响。

**修复**：

`src/PptInk.App/Ink/SmoothingFilter.cs`

- 引入 **OneEuro 自适应滤波**（Casiez et al., CHI 2012）替代固定 EMA：
  `α = 1/(1 + τ/Te)`，`fc = fcmin + β·|dx/dt|`；对 X/Y 各维护一个滤波器，
  导数用低通估计。**慢写强防抖、快写低延迟**。
- 参数与机型档案的 `EmaAlpha` 联动（线性映射 `minCutoff ∈ [0.6, 1.6]`），
  保留档案调参成果。

`src/PptInk.App/Ink/InkModels.cs`

- `BuildWidths` 增加**起笔渐入**：前 6 点宽度按 0.35 → 1.0（EaseOutQuad）渐入；
- 增加**自适应宽度低通**：`lowpassK = 0.32 + 0.23 × speedNorm`（快写灵敏跟随、
  慢写稳如泰山），取代固定 0.45；
- 新增 `ApplyLiftTaper`：抬笔时最后 8 点宽度按 1.0 → 0.25（EaseInQuad）渐出，
  形成「提笔由粗到细」的收笔笔锋。

`src/PptInk.App/Ink/InkEngine.cs`

- `OnStylusUp` 中提交前调用 `_live.ApplyLiftTaper()`。

`src/PptInk.App/UI/UnifiedStageWindow.InkRender.cs`

- `DrawBatch` 由 `LineTo` 折线升级为 `QuadraticBezierTo` 二次贝塞尔（中点法，
  与 `StrokeData.BuildGeometry` 同算法），笔画真正圆润；两点段退化直线保护。

## 构建与验证

### 编译验证（本环境实测）

前几轮受限于「无 Windows 环境无法构建 WPF」的认知，本轮发现 .NET 8 的
`EnableWindowsTargeting` 属性允许在 Linux 上还原 Windows 目标包并完成 WPF 编译：

```bash
export PATH=/opt/dotnet:$PATH
dotnet restore PptInk.sln -p:EnableWindowsTargeting=true
dotnet build PptInk.sln -c Release -p:EnableWindowsTargeting=true
# → Build succeeded. 0 Warning(s) 0 Error(s)
```

编译过程暴露并修复了一处真实 XAML 错误（`Tokens.xaml` MC4111：Trigger 无法定位
Freezable `ScaleTransform`）—— 这是仅靠静态检查无法发现的，验证了真实编译的价值。

### 便携包产出

```bash
dotnet publish src/PptInk.App/PptInk.App.csproj -c Release -r win-x64 \
  --self-contained true -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true \
  -p:DebugType=None -p:DebugSymbols=false -p:EnableWindowsTargeting=true \
  -o artifacts/win-x64
# → PptInk.exe: PE32+ executable (GUI) x86-64, for MS Windows（69MB，含 .NET 8 运行时）
```
